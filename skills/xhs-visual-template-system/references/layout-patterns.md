# Layout patterns

> Legacy reference. Use `page-recipes.md` and `component-library.md` for new production. Keep this file to translate or audit older template families without deleting their original logic.

## Selection rule

Choose a layout by communication job, available evidence, and channel. Do not choose by a vague style adjective.

| Pattern | Primary job | Best source material | Avoid when |
|---|---|---|---|
| Main-value cover | Earn attention | one strong value and recognizable scene | the value requires several caveats |
| Process explanation | Explain mechanism | 3–5 ordered actions | order is not important |
| Screenshot evidence | Establish trust | a real UI state or output | no screenshot actually proves the claim |
| Pain-point comparison | Create recognition | a credible before/after contrast | the “before” is exaggerated or invented |
| Feature collection | Enable scanning | 3–6 related capabilities | features serve unrelated audiences |
| Large-type atmosphere | Frame a topic or viewpoint | a short, strong statement | the title is long or proof-heavy |

## Pattern A — Main-value cover

Use for the first image.

Structure:

1. small category or scene label;
2. two- or three-line headline with one highlighted phrase;
3. one scene cue: product mark, simplified illustration, result preview, or cropped screenshot;
4. optional proof line or short conversion entry.

Keep the headline and scene cue dominant. Do not turn the cover into a complete feature catalog. A compact mechanism strip is acceptable only when the workflow itself is the value.

## Pattern B — Process explanation

Use for a mechanism with `3–5` ordered steps.

Structure:

1. short mechanism heading;
2. numbered steps with parallel grammar;
3. arrows or spatial flow only where order is not already obvious;
4. up to three outcome tags, or one result statement.

Choose horizontal steps when labels are short and the sequence should read at once. Choose vertical rows when labels need more detail or phone reading matters. Use the reviewed HR sequence as a proven four-step model: find candidates → AI judgment → automated outreach → result write-back.

## Pattern C — Screenshot evidence

Use when trust depends on seeing the product work.

Structure:

1. claim-led headline;
2. one dominant screenshot crop;
3. one primary highlight box or zoom;
4. one or two short annotations that name the action and result;
5. optional source or context line.

The screenshot should occupy the largest meaningful region. Avoid mosaics of tiny screenshots. If multiple screenshots prove sequential actions, split them into separate pages or use a clear `1 → 2 → 3` strip with readable crops.

## Pattern D — Pain-point comparison

Use for before/after, manual/automatic, scattered/unified, or slow/fast contrasts.

Structure:

1. reader-language headline;
2. left/right or top/bottom contrast;
3. muted “before” with no more than three concrete burdens;
4. brand-colored “after” with mechanism or result;
5. clear directional cue and restrained ×/✓ semantics.

Do not manufacture a dramatic enemy. Use specific repeated actions instead of vague claims such as “效率低” or “彻底解放双手.” The HR comparison works because the manual burdens are concrete and the automated side shows the four-step replacement mechanism.

## Pattern E — Feature collection

Use for product matrices, application catalogs, or grouped capabilities.

Structure options:

- one centered product mark with 4–6 surrounding jobs;
- a vertical numbered list with feature name plus one-line explanation;
- grouped cards by user job, such as operation, monitoring, collection, and export.

Rank capabilities visually. Use the feature collection as a series overview or a category page; use separate pages for details. The reviewed WeChat series works best when the first page offers overview and later pages split WeChat operations from Official Account collection.

## Pattern F — Large-type atmosphere cover

Use for a short, high-confidence topic or viewpoint.

Structure:

1. two or three large text lines;
2. one or two semantic color highlights;
3. atmospheric background or one subtle visual anchor;
4. generous negative space.

No feature list, screenshot, or decorative badge is required. Empty space must strengthen reading direction and tone. If the subject needs proof, follow with evidence pages rather than adding small proof elements to the cover.

## Recommended image-set structures

### Product or application introduction, 4 images

1. Main-value cover — promise one user outcome.
2. Process or feature grouping — show how it works.
3. Screenshot evidence — prove the decisive function or output.
4. Scenario/value page — identify who uses it and give a restrained next step.

### Complex workflow, 5 images

1. Main-value cover.
2. Pain-point comparison.
3. Process explanation.
4. Screenshot evidence for the key action.
5. Result evidence or conversion entry.

### Feature catalog, 3 images

1. Overview cover with the full category.
2. Feature collection for job group A.
3. Feature collection or evidence for job group B.

### Screenshot-led proof, 3 images

1. Claim-led cover.
2. Input/action screenshot evidence.
3. Output/result screenshot evidence.

Use fewer pages when the source material is weak. Never duplicate the same point across a cover, feature list, and process page.

## Channel adaptation

### Xiaohongshu

- Default to `1080 × 1440` portrait.
- Optimize the first image for thumbnail recognition.
- Use larger type and fewer words than an article illustration.
- Make each inner page understandable when viewed independently.

### WeChat Official Account

- Confirm the target cover ratio before designing.
- Keep essential title and subject away from likely platform crops.
- Use fewer, larger elements on wide covers.
- Treat the black-tech family as experimental until several real covers are reviewed together.

### Community sharing

- Prefer one self-contained card or a short set.
- Add context that survives forwarding: product name, scene, and next step.
- Avoid platform-specific instructions that become confusing outside the original channel.

## Storyboard format

Use this before implementation:

| Page | Type | One message | Headline | Evidence/visual | Screenshot role | Reader takeaway |
|---|---|---|---|---|---|---|

Every row must have one message. If the “one message” cell contains “and,” consider splitting it.
